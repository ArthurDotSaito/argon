Issues no Argon

Três jeitos de ver issues no Argon, com o mesmo visual do app (One Dark / One Light, sidebar "Visões", abas e linha de PR). Os mocks são clicáveis; cada um tem anotações numeradas, e passar o mouse numa anotação destaca o ponto correspondente na tela. Dados de exemplo são fictícios.

Proposta A · escolhida

Inbox unificada

Issue vira mais um tipo de item da caixa de entrada, nas mesmas seções e com o mesmo desenho de linha dos PRs.

  • "Needs you" passa a incluir issues
  • Grupo ISSUES na sidebar e filtro Tudo / PRs / Issues
  • Aba de issue no molde da aba de PR

Proposta B

Issues em espaço próprio

Aba e grupo próprios, longe da inbox de PRs. Lista densa com agrupamento, preview à direita e modo quadro, feita para triar.

  • Agrupar por repo, milestone, status ou tipo
  • Preview com atribuir, rotular e fechar sem abrir aba
  • Quadro pelo Status do GitHub Projects
Abrir mock →
Proposta C

Issue como início do trabalho

Suas issues por estágio (a fazer, em andamento, em review, pronto para merge), com o agente implementando a partir da issue.

  • Trilho issue → branch → PR → review → merge
  • "Implementar com IA" reusa as sessões de agente
  • PR e issue apontam um para o outro

Minha recomendação

Começar pela A, que é o pedido ao pé da letra ("ver issues como vejo os PRs") e reaproveita quase tudo: a busca da inbox já roda com type: ISSUE no GraphQL e hoje só filtra is:pr. Da C, eu traria já na primeira versão o chip "Fecha #n" no PR e o PR vinculado na issue, que custam pouco e ligam as duas telas. Na issue, o botão de IA é o "Agent Plan" (planejar a solução); no PR, "Revisar com IA" passa a se chamar "Agent Review". A B só vale se triar issues de várias pessoas for parte da sua rotina; aí ela pode entrar depois, como visões extras, sem refazer a A.

O que muda nos dados (vale para as três)

Busca (mesma query search do sync)
  • is:issue is:open assignee:@me
  • is:issue mentions:@me
  • is:issue author:@me, is:issue involves:@me
  • B: is:issue is:open org:X no:assignee para a fila sem responsável
  • No inbox_ids.graphql, um ... on Issue ao lado do ... on PullRequest
Campos de Issue (conferidos no schema GraphQL)
  • state + stateReason (COMPLETED, NOT_PLANNED, DUPLICATE, REOPENED)
  • issueType, labels, assignees, milestone
  • closedByPullRequestsReferences para o PR vinculado (A e C)
  • subIssuesSummary / parent para sub-issues
  • projectItems para Status e prioridade (só B)
