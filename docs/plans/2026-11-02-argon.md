# Plano: Argon — cliente desktop de Pull Requests

**Objetivo:** app desktop nativo (Rust + GPUI Kit) que trata Pull Requests do GitHub como uma caixa de e-mail, com review de código completa e reviews conduzidas por agentes de IA via ACP.

**Restrições (literais, vindas do pedido e das decisões aprovadas):**

- Nome do produto, do repositório e dos crates: **Argon** (`C:\project\Argon`, crates `argon-*`).
- UI: **GPUI Kit** (`gpui-kit` 0.8.x, que fixa e reexporta o GPUI; versão exata fica no `Cargo.lock`). Ícones Lucide via `gpui-kit-assets`.
- Direção visual **Zed**: dock esquerdo (visões/repos), área central com abas (preview tab em itálico, fixada com duplo clique; splits), dock direito (Agent Panel), dock inferior (Actions/log), command palette (`Ctrl+K`), status bar com toggles de dock, tema **One Dark** (padrão) e **One Light**. Referência de layout: `C:\project\design\proposta-2-foco\` + "linha de motivo" de `C:\project\design\proposta-3-papel\`. Requisitos de tela: `C:\project\design\BRIEF.md`.
- Plataforma do v1: **Windows** (código multiplataforma; CI e instalador só Windows).
- GitHub: autenticação **reaproveitada do `gh`** (`gh auth token --hostname <host>`), dados via **GraphQL/REST direto** (`reqwest`). Token só em memória. Suporte a github.com e GitHub Enterprise (host do `hosts.yml` do gh).
- Agentes: **ACP (Agent Client Protocol)** para Claude Code, Codex, OpenCode e Command Code; **Antigravity (`agy`) via modo headless** (não está no registro ACP). O agente **nunca publica** no GitHub — achados viram rascunhos locais.
- Visões: Inbox, Needs you, Your PRs, Waiting on others, Changes requested, Ready to merge, Already done — regras na Tarefa 2.
- Variáveis de template de prompt: `{{pr.title}}`, `{{pr.number}}`, `{{pr.url}}`, `{{pr.body}}`, `{{repo}}`, `{{base}}`, `{{head}}`, `{{diff}}`, `{{files}}`, `{{previous_reviews}}`, `{{ci_failures}}`.
- Diretórios: config em `%APPDATA%\Argon\` (`config.toml`, `prompts\*.md`); dados em `%LOCALAPPDATA%\Argon\` (`argon.db`, `repos\`, `worktrees\`, `logs\`).
- Idioma da UI: pt-BR, mantendo termos do GitHub em inglês (PR, commit, diff, merge, Actions, review, approve, request changes, draft).

**Política de testes:** repo novo, sem convenção — vale a política padrão do NDK: testar só lógica pura de `argon-core`, desserialização de respostas do GitHub (fixtures JSON) e o store em SQLite em memória. UI, wiring e chamadas de processo ficam sem teste.

**Fora de escopo do v1 (YAGNI):** macOS/Linux empacotado, tray icon, adiar/snooze, grupos customizados, stacked PRs, MCP server próprio para os agentes, edição de código pelo app.

## Arquitetura

```
C:\project\Argon
  Cargo.toml                (workspace)
  crates/
    argon-core/             domínio + lógica pura (classificação, diff, templates, achados, config)
    argon-github/           auth via gh, cliente GraphQL/REST, queries/mutations
    argon-store/            SQLite (rusqlite bundled + rusqlite_migration)
    argon-agents/           registro/detecção, sessão ACP, adaptador headless, worktrees
    argon-app/              binário GPUI (workspace, docks, views)
  assets/                   fontes (IBM Plex Sans, Lilex — OFL), temas, ícone
  docs/plans/  docs/agents.md
```

- **Concorrência:** um runtime **tokio** numa thread dedicada (`Services`) faz rede, processos e SQLite; a UI conversa com ele por canais (`futures::channel`) e aplica resultados em entidades GPUI via `cx.spawn`. Nada bloqueante na thread da UI.
- **Fluxo de dados:** `SyncService` → `Store` (fonte da verdade local) → evento `InboxChanged` → `InboxModel` (entidade GPUI) → views.
- **Ordem das fases:** cada fase termina com o app rodando e utilizável.

## Tarefa 2: Domínio e classificação de visões  [depende da Tarefa 1]

- **Arquivos:** `crates/argon-core/src/{lib.rs, model.rs, views.rs, reason.rs, time.rs}`
- **O quê:** tipos do domínio e as regras puras que decidem em quais visões um PR aparece, a "linha de motivo" e o agrupamento por data.
- **Interfaces (produz):**
  ```rust
  pub struct PrId(pub String);                    // node id GraphQL
  pub enum PrState { Open, Closed, Merged }
  pub enum ReviewDecision { Approved, ChangesRequested, ReviewRequired }
  pub enum ChecksState { Success, Failure, Pending, Error }   // None = sem checks
  pub enum Mergeable { Mergeable, Conflicting, Unknown }
  pub enum ReviewState { Approved, ChangesRequested, Commented, Dismissed, Pending }
  pub struct Involvement { pub requested: bool, pub assigned: bool, pub authored: bool, pub reviewed: bool }
  pub struct LatestReview { pub author: String, pub state: ReviewState, pub submitted_at: DateTime<Utc> }
  pub struct PullRequest {
      pub id: PrId, pub host: String, pub repo: String /* owner/name */, pub number: u64,
      pub title: String, pub url: String, pub author: String, pub is_draft: bool, pub state: PrState,
      pub base: String, pub head: String, pub additions: u32, pub deletions: u32, pub changed_files: u32,
      pub comments: u32, pub review_decision: Option<ReviewDecision>, pub checks: Option<ChecksState>,
      pub mergeable: Mergeable, pub requested_reviewers: Vec<String>, pub assignees: Vec<String>,
      pub latest_reviews: Vec<LatestReview>, pub head_committed_at: DateTime<Utc>,
      pub created_at: DateTime<Utc>, pub updated_at: DateTime<Utc>, pub closed_at: Option<DateTime<Utc>>,
      pub involvement: Involvement,
  }
  bitflags! { pub struct ViewSet: u8 { INBOX, NEEDS_YOU, YOUR_PRS, WAITING_ON_OTHERS, CHANGES_REQUESTED, READY_TO_MERGE, ALREADY_DONE } }
  pub fn classify(pr: &PullRequest, me: &str, now: DateTime<Utc>, closed_window_days: i64) -> ViewSet;
  pub fn is_ready(pr: &PullRequest) -> bool;
  pub enum Reason { ReviewRequestedBy(String), AssignedBy(Option<String>), ChangesRequestedBy(String), WaitingOn(Vec<String>), ReadyToMerge, ApprovedByYouWaitingAuthor, CiFailed, Conflict, Tracking }
  pub fn reason(pr: &PullRequest, me: &str) -> Reason;
  pub enum DateBucket { Today, Yesterday, ThisWeek, Older }
  pub fn date_bucket(now: DateTime<Local>, ts: DateTime<Local>) -> DateBucket;
  ```
- **Regras (exatas):**
  - `is_ready` = aberto ∧ ¬draft ∧ (`review_decision == Approved` ∨ (`review_decision == None` ∧ algum `latest_reviews` Approved)) ∧ `checks ∈ {Success, None}` ∧ `mergeable == Mergeable`.
  - **INBOX**: aberto, ou fechado/mergeado com `closed_at` dentro de `closed_window_days`.
  - **NEEDS_YOU**: aberto ∧ autor ≠ me ∧ (`requested` ∨ `assigned`) ∧ não existe review meu com `submitted_at > head_committed_at`.
  - **YOUR_PRS**: aberto ∧ autor == me.
  - **WAITING_ON_OTHERS**: YOUR_PRS ∧ ¬draft ∧ decisão ∉ {Approved, ChangesRequested} ∧ `requested_reviewers` não vazio.
  - **CHANGES_REQUESTED**: YOUR_PRS ∧ `review_decision == ChangesRequested`.
  - **READY_TO_MERGE**: YOUR_PRS ∧ `is_ready`.
  - **ALREADY_DONE**: aberto ∧ autor ≠ me ∧ meu último review é Approved ∧ `is_ready`.
  - Ordem de toda visão: `updated_at` desc.
- **Testes:** sim — tabela de casos para cada regra de `classify`, `is_ready`, `reason`, `date_bucket` (virada de dia e de semana).
- **Pronto quando:** `cargo test -p argon-core` verde com ≥1 caso positivo e ≥1 negativo por visão.

## Tarefa 4: Cliente GitHub — auth e sincronização da inbox  [depende da Tarefa 2]

- **Arquivos:** `crates/argon-github/src/{lib.rs, auth.rs, client.rs, inbox.rs, queries/inbox.graphql}`, `crates/argon-github/tests/fixtures/*.json`
- **O quê:** descobre as contas do gh lendo `hosts.yml` (`%GH_CONFIG_DIR%` ou `%APPDATA%\GitHub CLI\hosts.yml`), obtém o token com `gh auth token --hostname <host>` (cobre token no keyring do Windows). Cliente HTTP com endpoints corretos para github.com (`api.github.com`) e GHE (`https://<host>/api/graphql`, `/api/v3`). Sincronização da inbox com buscas GraphQL `search(type: ISSUE)` paginadas (100/página), unindo resultados por `PrId` e preenchendo `Involvement`:
  1. `is:pr is:open review-requested:@me` → `requested` (inclui pedidos por time)
  2. `is:pr is:open assignee:@me` → `assigned`
  3. `is:pr author:@me updated:>=<now − closed_window_days>` → `authored`
  4. `is:pr is:open reviewed-by:@me -author:@me` → `reviewed`
  5. para cada org rastreada do host: `is:pr org:<org> updated:>=<now − closed_window_days>`
  Também `viewer { login organizations(first:100) { nodes { login viewerCanAdminister } } }`. Respeita `rateLimit { remaining resetAt }` (pula ciclo se `remaining < 200`).
- **Interfaces (produz):**
  ```rust
  pub struct Account { pub host: String, pub login: String }
  pub fn discover_accounts() -> Result<Vec<Account>>;
  pub async fn token_for(host: &str) -> Result<String>;
  pub struct GithubClient { /* host, token, reqwest::Client */ }
  impl GithubClient {
      pub fn new(host: &str, token: String) -> Self;
      pub async fn viewer(&self) -> Result<Viewer>; // login + Vec<OrgInfo { login, can_admin }>
      pub async fn fetch_inbox(&self, me: &str, tracked_orgs: &[String], closed_window_days: i64) -> Result<Vec<PullRequest>>;
  }
  ```
- **Testes:** sim — desserialização de fixtures (resposta real anonimizada do `search`) para `PullRequest`; merge de `Involvement` quando o mesmo PR aparece em várias buscas.
- **Pronto quando:** `cargo test -p argon-github` verde e `cargo run -p argon-github --example inbox_dump` imprime os PRs da conta logada, com contagem de `requested` igual a `gh search prs --review-requested=@me --state=open --json number | jq length`.

## Riscos conhecidos

- **gpui-kit em evolução rápida (0.x):** fixar versão no `Cargo.lock` e só atualizar entre fases.
- **Componentes não confirmados no gpui-kit** (select, dialog, popover, tooltip, badge, avatar): se faltarem, implementar em `argon-app/src/ui/` sobre `gpui-base` — custo de 1–2 dias, não muda o plano.
- **Diff view é componente próprio** (gpui-kit não tem): é a peça de UI mais cara (Tarefa 15).
- **Seleção de modelo e retomada variam por agente:** fechadas pelo spike (Tarefa 17) antes de qualquer UI de agente.
- **Busca do GitHub limitada a 1.000 resultados por query:** orgs muito grandes devem usar o filtro `updated:>=` (já previsto) ou ser rastreadas por repo.
